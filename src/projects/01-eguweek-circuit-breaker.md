# 이구위크 트래픽 대응을 위한 장애 격리 및 캐싱 구조 개선

- **역할**: 전시 시스템 백엔드 개발자
- **팀 규모**: [UNVERIFIED: 확인 필요]

## Situation (배경)
이구위크 대규모 프로모션 대비 과정에서 외부 API(쿠폰, 유저, 활성화 보상 등) 장애가 서비스 전반에 전파될 수 있는 구조적 취약점이 식별됨. 특히 외부 도메인 API 의존도가 높아 단일 장애점으로 인한 연쇄 장애 리스크가 존재.

## Task (과제)
외부 API 장애 시에도 핵심 기능이 정상 운영될 수 있도록 장애 격리 구조를 설계하고, 지연을 완화할 캐싱 전략을 수립.

## Action (행동)
### 기술적 선택
- **사용 기술**: Resilience4j Circuit Breaker, Redis, Timeout 최적화
- **선택 이유**: API Gateway 일괄 차단 대신 서비스 레벨 적용으로 도메인별 세밀한 graceful degradation 구현
- **고려한 대안**: API Gateway 레벨 일괄 차단
- **트레이드오프**: 서비스 레벨 적용은 설정/관리 복잡도가 높지만, 도메인별 독립적인 장애 대응 가능

### 구현 상세
- Resilience4j Circuit Breaker 도입으로 외부 의존성 장애 전파 차단
- Timeout 최적화: connect 100ms / read 1s
- Redis 캐싱 적용으로 지연 완화
- 팀 SLI/SLO 체계와 연계한 모니터링 대상 API 식별 및 적용

### 기술적 도전
- API Gateway 일괄 차단 방식이 아닌 서비스 레벨에서의 세밀한 장애 격리 구현
- 도메인별 graceful degradation 전략 수립
