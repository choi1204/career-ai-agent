# /assess-capability

## 목적
축적된 모든 데이터를 기반으로 "나라는 사람"의 종합 직무 역량을 평가합니다.
강점/약점을 분석하고, 강점 강화 + 약점 완화를 위한 실행 가능한 로드맵을 생성합니다.

## 에이전트 역할
config/agent-roles.md → Career Advisor + Interview Coach + Market Analyst

## 입력
- src/user-profile.md (필수)
- src/projects/*.md (프로젝트 역량)
- outcome/interview/*.md (면접 시뮬레이션 결과)
- outcome/3_review/*.md (이력서 리뷰 결과)
- outcome/analysis/*.md (JD 분석/기업 리서치 결과)
- outcome/learning/*.md (학습 기록)
- src/jd/*.md (타깃 포지션)
- config/capability-dimensions.md (평가 차원)

## 실행 절차

### Phase 1: 데이터 수집 & 정량화
1. 모든 소스에서 역량 신호 추출:
   - 프로젝트: 기술 스택, 아키텍처 경험, 임팩트 규모
   - 면접 결과: 주제별 달성 레벨 (L1~L5)
   - 이력서 리뷰: 평가 등급
   - JD 분석: 매칭률, 갭 항목

### Phase 2: 역량 차원별 평가
config/capability-dimensions.md 기준으로 각 차원 평가:

| 차원 | 평가 방법 |
|------|----------|
| 기술 역량 | 프로젝트 기술 스택 + 면접 L레벨 |
| 문제 해결 | 프로젝트 도전/해결 사례 + 면접 L3~L5 |
| 시스템 설계 | 아키텍처 경험 + 트레이드오프 이해도 |
| 커뮤니케이션 | 이력서 가독성 + 면접 구조화 능력 |
| 임팩트/성과 | 정량적 성과 + 비즈니스 기여도 |
| 성장 가능성 | 회고 품질 + 학습 패턴 |
| 시장 적합성 | JD 매칭률 + 기술 트렌드 부합도 |

각 차원: 1~5점 + 근거

### Phase 3: 강점/약점 분석
- **핵심 강점** (상위 3개):
  - 왜 강점인지 (근거)
  - 어떻게 더 강화할지 (액션)
  - 이력서/면접에서 어떻게 어필할지

- **핵심 약점** (상위 3개):
  - 왜 약점인지 (근거)
  - 완화 전략 (단기 vs 장기)
  - 면접에서 질문받으면 어떻게 대응할지

- **숨겨진 강점** (본인이 인지 못할 수 있는):
  - 프로젝트 패턴에서 발견된 역량
  - 면접 답변에서 드러난 사고방식

### Phase 4: 개선 로드맵
타깃 포지션 기준으로 우선순위화:

```
[즉시] (1~2주) — 이력서/면접 표현 개선
  → 기존 강점을 더 잘 보여주는 작업

[단기] (1~3개월) — 약점 완화
  → 학습 + 사이드 프로젝트 + 면접 연습

[중기] (3~6개월) — 역량 확장
  → 새 기술/경험 영역 확보

[장기] (6개월+) — 커리어 레벨업
  → 시니어/리드급 역량 구축
```

각 항목에 구체적 액션 + 추천 커맨드 포함

### Phase 5: 포지션별 적합도 매트릭스 (JD 있을 때)
각 타깃 포지션별:
- 현재 적합도 (%)
- 가장 큰 갭
- 갭 해소에 필요한 액션
- 예상 준비 기간

## 출력
- outcome/analysis/capability_v{N}_{YYYYMMDD_HHmmss}.md
  - 역량 레이더 차트 (텍스트 기반)
  - 강점/약점 상세 분석
  - 개선 로드맵
  - 포지션별 적합도 (JD 있을 때)

## 검증 훅
- 모든 평가에 근거 경로 표시 (어떤 파일의 어떤 내용 기반인지)
- 데이터 없는 차원은 [데이터 부족] 표시 + 수집 방법 안내

## 규칙
- **과장 금지**: 프로젝트 1개에 기술 사용 = "경험 있음"이지 "전문가"가 아님
- **솔직한 평가**: 약점을 완곡하게 포장하지 않음
- **근거 필수**: 모든 점수에 "왜 이 점수인지" 1줄 이상 근거
- **비교 기준 명시**: "시장 평균" "타깃 포지션 요구 수준" 대비 어디인지
- 데이터가 부족하면 추측하지 않고 "평가 불가, 다음 데이터가 필요합니다" 표시

## 제안 트리거
- 면접 데이터가 없으면:
  → "/mock-interview 를 먼저 실행하면 기술 역량을 더 정확히 평가할 수 있습니다"
- 프로젝트가 1~2개뿐이면:
  → "/intake-project 로 더 많은 프로젝트를 등록하면 역량 분석이 풍부해집니다"
- 특정 약점에 대응하는 커맨드가 있으면:
  → "기술 깊이가 약합니다 → /mock-interview 로 L3~L5 연습을 추천합니다"
- 코딩테스트 역량 데이터가 없으면:
  → "/coding-test 로 알고리즘 역량도 함께 평가해보세요"
- 로드맵 생성 후:
  → "이 로드맵을 GitHub Issue로 등록해서 진행 상황을 추적할까요?"
