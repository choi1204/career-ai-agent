# /coding-test

## 목적
코딩테스트 대비를 위한 문제 풀이 연습, 풀이 리뷰, 취약 유형 분석을 수행합니다.
실전 코딩테스트 환경을 시뮬레이션하고 체계적으로 역량을 추적합니다.

## 에이전트 역할
config/agent-roles.md → Interview Coach (코딩테스트 특화)

## 입력
- 사용자 선택: 모드 (연습 / 모의시험 / 풀이리뷰 / 취약분석)
- src/user-profile.md (기술 스택 → 언어 선택 참고)
- outcome/learning/coding-test-log.md (풀이 이력, 있으면)
- config/coding-test-categories.md (유형 분류)

## 모드별 실행 절차

### 모드 1: 연습 (practice)
1. 유형 선택 (사용자에게 물어봄):
   - 자료구조: 배열, 스택/큐, 해시, 트리, 그래프, 힙
   - 알고리즘: 정렬, 탐색, DP, 그리디, BFS/DFS, 이분탐색, 투포인터
   - 기타: 구현, 문자열, 수학, 시뮬레이션
   - 랜덤 (취약 유형 가중치 반영)

2. 난이도 선택: Easy / Medium / Hard

3. 문제 출제:
   - 문제 설명 + 입출력 예시 + 제약 조건
   - 시간 제한 안내 (Easy: 20분, Medium: 30분, Hard: 45분)

4. 사용자 풀이 수신 후 리뷰:
   - **정확성**: 모든 케이스 통과 여부
   - **시간복잡도**: O 표기법 분석
   - **공간복잡도**: 메모리 사용 분석
   - **코드 품질**: 가독성, 변수명, 엣지케이스 처리
   - **최적화 여부**: 더 나은 풀이가 있는지

5. 모범 답안 제시:
   - 브루트포스 → 최적화 과정 설명
   - 핵심 아이디어/패턴 강조
   - 유사 문제 유형 안내

### 모드 2: 모의시험 (exam)
1. 실전 환경 시뮬레이션:
   - 3~4문제 세트 (Easy 1 + Medium 2 + Hard 1)
   - 총 시간: 120분
   - 문제를 한 번에 모두 제시

2. 사용자 풀이 수신 후:
   - 문제별 정답/부분정답/오답 판정
   - 총점 산출 (기업별 기준 참고)
   - 시간 배분 분석

3. 전체 피드백:
   - 통과 여부 예측 (기업별 커트라인 참고)
   - 시간 관리 피드백
   - 풀이 순서 전략 피드백

### 모드 3: 풀이리뷰 (review)
1. 사용자가 풀었던 문제/코드를 제출
2. 리뷰:
   - 정확성 검증
   - 더 나은 풀이 제안
   - 시간/공간 복잡도 개선
   - 패턴 인식 ("이 문제는 {패턴}의 변형입니다")
   - 면접에서 설명하는 방법

### 모드 4: 취약분석 (analyze)
1. outcome/learning/coding-test-log.md 분석
2. 유형별 정답률 산출
3. 취약 유형 Top 3 식별
4. 각 취약 유형별:
   - 핵심 패턴 정리
   - 추천 연습 문제 (난이도 순)
   - 풀이 템플릿
5. 학습 로드맵 생성

## 출력
- outcome/learning/coding-test-log.md (풀이 이력 누적)
  ```
  | 날짜 | 유형 | 난이도 | 결과 | 시간 | 핵심패턴 | 메모 |
  ```
- outcome/interview/coding_{mode}_v{N}_{YYYYMMDD_HHmmss}.md (세션 기록)

## 규칙
- **정답을 먼저 알려주지 않음**: 힌트 → 재시도 → 모범답안 순서
- **힌트 단계**:
  1. 방향 힌트: "이 문제는 {자료구조/알고리즘}을 생각해보세요"
  2. 구체 힌트: "이 부분에서 {패턴}을 적용하면..."
  3. 모범 답안: 전체 코드 + 설명
- **시간복잡도 필수**: 모든 풀이에 시간/공간 복잡도 명시
- **실전 연습**: 모의시험 모드에서는 중간에 답을 알려주지 않음
- 풀이 이력은 항상 coding-test-log.md에 누적

## 제안 트리거
- 특정 유형 정답률이 50% 미만이면:
  → "이 유형은 집중 연습이 필요합니다. 해당 유형 5문제 연속 풀이를 추천합니다"
- 모의시험에서 시간 부족으로 못 푼 문제가 있으면:
  → "시간 관리 전략: Easy를 15분 내 해결하고 Medium에 집중하세요"
- 타깃 기업이 있으면:
  → "이 기업은 {유형} 문제를 자주 출제합니다. 해당 유형을 우선 연습하세요"
- 10문제 이상 풀었으면:
  → "취약분석 모드로 체계적으로 분석해볼까요? /coding-test analyze"
- 코딩테스트 실력이 면접 수준 이상이면:
  → "/assess-capability 로 종합 역량 평가에 코딩 역량도 반영하세요"
