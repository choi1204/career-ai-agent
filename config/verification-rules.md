# 팩트체크 규칙

## 검증 대상
1. **정량적 수치**: %, 건수, 시간, 금액, 성능 지표
2. **기술적 주장**: 아키텍처 선택, 성능 개선, 최적화
3. **역할/기여도**: "단독 개발", "설계 주도", "팀 리드"
4. **기간**: 프로젝트 기간, 경력 기간

## 검증 소스 우선순위
1. `src/evidence/` (외부 증거: 스크린샷, 대시보드, 문서 링크)
2. `src/projects/*.md` (프로젝트 상세 기록)
3. `src/user-profile.md` (사용자 자기 진술)

## 태깅 규칙
| 태그 | 의미 | 조건 |
|------|------|------|
| ✅ VERIFIED | 외부 증거 확인됨 | evidence/에 출처 존재 |
| 📝 SELF_REPORTED | 자기 진술만 있음 | projects/profile에는 있으나 외부 증거 없음 |
| ⚠️ UNVERIFIED | 확인 불가 | 어디에서도 확인 불가 → 출처 요청 |
| ❌ CONFLICT | 수치/내용 불일치 | 출처와 수치가 다름 → 수정 필요 |
| 🔍 EXAGGERATED | 과장 의심 | 원본 대비 20% 이상 차이 → 검토 필요 |

## 이력서 반영 규칙
| 태그 | 이력서 사용 | 비고 |
|------|------------|------|
| ✅ VERIFIED | 수치 그대로 사용 | |
| 📝 SELF_REPORTED | 사용 가능 | 면접 설명 준비 필요 |
| ⚠️ UNVERIFIED | 수치 사용 **불가** | 정성적 표현으로 대체 |
| ❌ CONFLICT | 사용 **불가** | 원본 기준 수정 |
| 🔍 EXAGGERATED | 사용 **불가** | 원본 수치로 교체 |

## 자동 검증 스크립트
- `scripts/extract-metrics.sh` — 마크다운에서 수치 자동 추출
- `scripts/check-evidence.sh` — 추출된 수치와 evidence/ 대조
- `scripts/validate-resume.sh` — 최종본 검증 태그 잔존 확인
