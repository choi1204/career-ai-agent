# 기술적 깊이 체크리스트

## L1~L5 기준

### L1 (What): 무엇을 했는지
- [ ] 사용 기술 목록
- [ ] 구현 기능 설명

### L2 (Why): 왜 선택했는지
- [ ] 기술/패턴 선택 이유
- [ ] 해결하려는 비즈니스 문제 (맥락)

### L3 (Alternative): 대안 비교
- [ ] 검토한 대안 목록 (최소 2개)
- [ ] 각 대안의 장단점
- [ ] 최종 선택 이유 (대안 대비 우위)

### L4 (Tradeoff): 트레이드오프 + 시행착오 ← 최소 목표
- [ ] 선택의 단점 / 포기한 것
- [ ] 제약 조건 (시간/리소스/기술 한계)
- [ ] 시행착오 과정 (처음 시도 → 실패 → 개선)
- [ ] 핵심 인사이트 ("이것을 깨달았다")

### L5 (Retrospective): 회고 + 확장
- [ ] 다시 한다면 어떻게 할지 (구체적 대안)
- [ ] 규모 확장 시 병목점
- [ ] 배운 점이 이후 프로젝트에 어떻게 적용되었는지

## "아하 모먼트" 유발 패턴

1. **반전**: "처음에 A를 시도했지만 실패 → B로 전환한 이유는..."
2. **제약 극복**: "이상적으로는 C지만, D 제약 때문에 E를 선택..."
3. **수치 기반 결정**: "X ms에서 Y ms로 줄여야 했고, 프로파일링 결과..."
4. **팀 설득**: "시니어가 A를 제안했지만, B가 나은 이유를 데이터로 설득..."
5. **실패에서 배움**: "첫 배포에서 Z 이슈 발생 → 근본 원인은... → 이후 모든 서비스에 적용"
