# /multi-review

## 목적
이력서를 3가지 다른 관점에서 **동시에** 리뷰하여 종합적인 피드백을 제공합니다.
단일 관점 리뷰(`/review-resume`)보다 더 넓은 범위의 개선점을 발견합니다.

## 서브에이전트 (병렬 3관점)
3개 서브에이전트가 각각 다른 페르소나로 리뷰합니다:

| 관점 | 서브에이전트 | 페르소나 | 평가 초점 |
|------|------------|---------|----------|
| HR 관점 | career-resume-writer | 채용 담당자 | 첫인상, 가독성, 커리어 흐름 일관성 |
| Tech Lead 관점 | career-capability-assessor | 기술 리더 | 기술 깊이, 아키텍처 의사결정, 문제해결 |
| Culture Fit 관점 | career-interview-coach | 팀 매니저 | 가치관, 성장 마인드셋, 협업 역량 |

## 입력
- outcome/ 의 최신 이력서 (초안 또는 최종본)
- src/user-profile.md
- src/projects/*.md
- src/jd/*.md (있으면)

## 실행 절차

### Step 1: 병렬 3관점 리뷰 실행
3개 서브에이전트를 **동시에** Task 도구로 호출합니다:

```
# 1) HR 관점 — 채용 담당자
Task(subagent_type="career-resume-writer", prompt="""
[리뷰 모드 — HR 관점]
당신은 대기업 채용 담당자입니다. 하루에 100개의 이력서를 봅니다.

대상 이력서: {이력서 경로}

평가 항목:
1. 첫인상 (10초 스캔): 핵심 역량이 바로 눈에 들어오는가?
2. 커리어 흐름: 경력 전환이 자연스러운가? 공백 기간은?
3. 가독성: 구조, 분량, 용어가 적절한가?
4. 차별화: 다른 지원자와 차별되는 포인트가 있는가?

각 항목 A~D 등급 + 구체적 개선 포인트 + Before/After 예시
""")

# 2) Tech Lead 관점 — 기술 리더
Task(subagent_type="career-capability-assessor", prompt="""
[리뷰 모드 — Tech Lead 관점]
당신은 시니어 엔지니어/기술 리더입니다.

대상 이력서: {이력서 경로}
참조: src/projects/*.md

평가 항목:
1. 기술 깊이: 단순 사용 vs 깊은 이해가 드러나는가?
2. 아키텍처 의사결정: WHY가 보이는가?
3. 임팩트 규모: 성과가 비즈니스/시스템 수준인가?
4. 기술 트렌드: 시장에서 경쟁력 있는 스택인가?

각 항목 A~D 등급 + "이 부분을 면접에서 물어볼 것" 표시
""")

# 3) Culture Fit 관점 — 팀 매니저
Task(subagent_type="career-interview-coach", prompt="""
[리뷰 모드 — Culture Fit 관점]
당신은 팀 매니저입니다. 함께 일할 사람을 찾고 있습니다.

대상 이력서: {이력서 경로}
참조: src/user-profile.md

평가 항목:
1. 성장 마인드셋: 도전과 학습의 흔적이 보이는가?
2. 협업 역량: 팀 기여, 커뮤니케이션이 드러나는가?
3. 주인의식: 문제를 스스로 발견하고 해결한 경험이 있는가?
4. 가치관 일치: 이 사람과 함께 일하고 싶은가?

각 항목 A~D 등급 + 면접에서 확인할 질문 리스트
""")
```

### Step 2: 통합 리포트 생성
메인 세션이 3관점 결과를 통합합니다:

```markdown
## 종합 평가 매트릭스
| 항목 | HR | Tech Lead | Culture Fit | 종합 |
|------|-----|-----------|-------------|------|

## 관점별 Top 개선 포인트
### HR 관점
### Tech Lead 관점
### Culture Fit 관점

## 우선 개선 항목 (3관점 교차 분석)
→ 여러 관점에서 동시에 지적된 항목 = 최우선 개선
```

## 출력
- outcome/3_review/multi_review_v{N}_{YYYYMMDD_HHmmss}.md
  - 3관점 개별 리뷰
  - 종합 평가 매트릭스
  - 교차 분석 기반 우선 개선 항목

## 규칙
- 3관점의 평가가 충돌할 수 있음 → 충돌 시 양쪽 의견을 모두 기록
- 추상적 피드백 금지 (모든 피드백에 Before/After 또는 구체적 예시)
- 평가는 보수적으로 (A 등급 남발 금지)

## 제안 트리거
- 3관점 모두에서 지적된 약점이 있으면:
  → "3명의 리뷰어가 모두 지적한 항목입니다. 최우선으로 개선하세요"
- Tech Lead 관점에서 기술 깊이가 부족하면:
  → "/mock-interview 로 기술 깊이를 보강하면 이력서에도 반영할 수 있습니다"
- Culture Fit 관점에서 협업 경험이 부족하면:
  → "프로젝트 설명에 팀 내 역할과 기여를 더 구체적으로 추가하세요"
